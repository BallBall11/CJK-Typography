强调 · *文字*

这是一个强调的中文短语，和 emphasis in Latin 排在同一行里。

中文强调交给重楷体：笔画带书写感，长文里靠字面本身区分语气，不靠机械倾斜。 西文仍是原生斜体，两种变体在同一行里各说各话，不会互相抢注意力。 楷体字面偏小、灰度略高，正适合轻量强调——它不会像加粗那样把行流截断。

粗体 · **文字**

这一句里有加粗的中文短语，也有 bold in Latin。

字重完全交给默认主题的 --bold-weight（600）。中文从 400 抬到 600 时字面骨架依旧清楚，不会糊成一团；加粗颜色沿袭 --bold-color， 换配色或第三方配色方案时自动跟随，不需要主题再维护一份。

粗斜体 · ***文字***

粗斜体的中文短语，以及区内嵌套加粗收尾。

中文仍然走楷体字面，只把字重抬到默认粗体，不叠着重号。 中文行距紧，着重号会在基线上下挤出多余空隙，一段里出现几处就足以毁掉整段的行节奏。

行内代码

执行 npm install --save 依赖 之后，再看 const 变量 = '中文';。

代码里的强调会被中和："前缀 变量名 常量 后缀"。

中文、全角标点改用等宽中文字面，与西文按照同一格宽推进，注释和缩进不会错位， 复制出去的代码也不会因为字宽不齐而歪掉。西文依旧使用默认等宽栈， 连字与语法高亮行为不变；行内代码里的斜体、粗体一律归一，避免等宽网格被打断。

代码块

function 计算(参数) {
  // 中文注释与 comment 混排
  return 参数 * 2; // 返回 结果
}

中文注释、中文标识符与西文共用一套列宽，竖向对齐靠字体自身完成。 代码里的强调也会被中和，*** 之类的混排不会破坏等宽网格。

中西文间距

中文与 Latin 混排 2024 年、PDF、HTML、iPhone 15 之间不需要手动敲空格。

若内嵌 Chromium 支持 text-autospace，中文与西文/数字之间会自动留出气口； 不支持时这条声明被整条忽略，版面与其他部分完全一致，不会出现半生效的怪状态。
